# Правила разработки проекта AmoCRM Analytics

## 1. Режим быстрой разработки (БЕЗ пересборки Docker на каждый чих)
Пересборка Docker (`docker compose up -d --build`) занимает по 30–50 секунд и блокирует работу.
Поэтому агент соблюдает разумный регламент:
1. **Быстрая разработка**: в процессе внесения правок НЕ запускать пересборку Docker на каждую строчку.
2. **Проверка**: перед фиксацией изменений проверить типы/синтаксис (`npm run build` / `tsc --noEmit` для фронтенда, `python -m py_compile` для бэкенда).
3. **Фиксация в Git**: коммитить и пушить по завершении задачи или логического этапа:
   ```bash
   git add -A && git commit -m "<описание изменения>" && git push origin main
   ```
4. **Пересборка Docker**: выполнять ТОЛЬКО когда задача полностью готова и проверена, либо по прямой просьбе пользователя, либо если изменились зависимости (`package.json`, `requirements.txt`) или `Dockerfile`/`docker-compose.yml`.
5. **Защита от перезаписи**: если возникли нежелательные изменения от автосохранения IDE пользователя, восстанавливать состояние через `git restore .`.

## 2. Модульная архитектура (Зеркало бэкенда)
- Код фронтенда разделён по изолированным модулям:
  - `src/modules/01_time_analytics/`
  - `src/modules/02_bi_analytics/`
  - `src/modules/03_ai_predictions/`
  - `src/modules/ai_chat/`
  - `src/modules/admin/`
  - `src/modules/auth/`
  - `src/shared/`
- Любые доработки или новые сервисы добавляются изолированно в свои папки, не затрагивая код других сервисов.
- Запрещено раздувать страницы в монолиты (выносить вкладки, фильтры и графики в отдельные компоненты по 100–300 строк).
